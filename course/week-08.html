Week 08 / Systems

Build a domain and understand DNS

6 hours core+ 0–6 hours practicePrerequisite: Week 07

Active Directory Domain Services (AD DS) centralizes identities and policy. DNS service records help clients locate domain controllers. Kerberos provides ticket-based authentication and depends on name resolution and reasonably synchronized clocks. AD DS and Microsoft Entra ID are different identity systems.

Power-on plan: DC01 4 GB + WIN01 4 GB; all Linux and monitoring VMs off. Private switch. Domain: corp.example.test.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

1. Create DC01

Repeat Week 7’s Windows installation on a fresh VM named DC01, 4 GB RAM, 2 vCPU, 60 GB disk. Patch and activate before promotion, using Default Switch. Rename the guest DC01 and reboot. Shut down, attach CyberLab-Private, then set IPv4 to 10.77.0.10, mask 255.255.255.0, no gateway, preferred DNS 10.77.0.10. Use a distinct local Administrator password.

2. Install a new forest

DC01 • administrator PowerShell
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
Install-ADDSForest -DomainName "corp.example.test" -DomainNetbiosName "CORP" -InstallDNS

Choose and securely record the Directory Services Restore Mode password when asked. Read the prerequisite checks. A parent DNS delegation warning is expected for this isolated new test forest; other errors require investigation. Accept the restart. Sign in as CORP\Administrator. Never use this domain name or lab password for a real organization.

3. Validate the controller

DC01 • administrator PowerShell
Get-ADDomain
Get-ADForest
Get-Service NTDS,DNS,Netlogon
Resolve-DnsName -Type SRV _ldap._tcp.dc._msdcs.corp.example.test
dcdiag /test:dns

Confirm the domain and a service record pointing at DC01. DNS diagnostics may flag lack of internet resolution; this private domain must resolve its own records. Record each failure and distinguish intentional lack of internet from broken internal DNS.

4. Join WIN01

On WIN01 set its Ethernet preferred DNS to 10.77.0.10; retain 10.77.0.21/24 and no gateway. The domain client must use domain DNS, not a public resolver. Check the SRV lookup before joining.

WIN01 • administrator PowerShell
Resolve-DnsName -Type SRV _ldap._tcp.dc._msdcs.corp.example.test
Add-Computer -DomainName corp.example.test -Credential CORP\Administrator -Restart

Enter the domain administrator credential at the prompt. After restart, sign in with the domain Administrator for setup only. A member server is used here to avoid needing a separately licensed Windows client VM; it is not an exact desktop-client simulation.

5. Understand what changed

WIN01 • PowerShell
whoami /all
(Get-CimInstance Win32_ComputerSystem).Domain
nltest /dsgetdc:corp.example.test
klist

Compare local and domain identities. Draw client → DNS → domain controller, and mark where authentication and name lookup occur. Keep both VMs’ clocks close to the host. Do not add an internet adapter to the domain controller for convenience.

Pass this week

  • Domain DNS record and service status
  • WIN01 domain membership
  • Identity/DNS diagram

Explain without the guide

  • Why can a correct password fail if DNS is wrong?
  • What is the difference between CORP\Administrator and WIN01\Administrator?

If something fails

Join failure: check correct DNS, same Private switch, DC services, and time. An evaluation expiration is not an AD fault. Avoid rolling back only one machine in a domain pair; secure-channel state can diverge.

Optional practice · 0–6 extra hours

Inspect DNS Manager’s forward zone and _msdcs records. Explain SRV versus A records without changing them.
