Instructor edition

Mentor guide

Your role is to make the learner explain and verify systems rather than merely complete installations. His development experience helps with structured thinking; the course deliberately limits coding to useful administrative automation. Use the labs to discover which kind of security work he enjoys.

Weekly review · 30–45 minutes

  • 5 minutes: learner states the system and intended behavior without reading the guide.
  • 10 minutes: learner shows one positive and one negative test, with fresh output where feasible.
  • 10 minutes: ask why the control works and where it fails.
  • 5–10 minutes: introduce one reversible fault or ask for a diagnosis of an existing failure.
  • 5 minutes: record score, one improvement, and the next prerequisite. Keep the review within the six-hour core budget.

Fault bank · instructor controlled

Choose exactly one fault, record its prior state, and keep console access. Tell the learner the affected service, not the cause. Never alter the host’s actual networking, account, or data as an exam. Restore the original value after the learner’s attempt if needed.

Answer anchors

Foundations and identity
  • A private switch gives guest-to-guest networking; Default Switch adds connectivity. Failure of a public ping alone is not proof of isolation.
  • File access depends on identity, permissions, and parent-directory traversal; opening access broadly masks the cause.
  • DNS is required for domain discovery. Public DNS cannot resolve the private domain’s AD service records.
  • Group membership affects tokens; re-logon is necessary for clean access-change tests. Policy-editor configuration alone does not prove GPO application.
  • TLS requires identity/trust validation. A hash verifies bytes, not confidentiality.
Detection and response
  • A live source, agent, manager rule, index, and dashboard have distinct failure symptoms. A logtest match is not proof of ingestion.
  • Sysmon replay proves captured data and parsing; it does not prove continuous native Windows collection.
  • The Suricata lab sees UBU01 traffic. Neither sharing a switch nor an “active” service establishes full coverage.
  • An alert needs context and disposition. Training markers/pings are expected and cannot justify an attack claim.
  • Triage preserves volatile information before containment where feasible. A restore must be validated by content/hash and actual usability.
Cloud
  • Resource Contributor and data roles are separate; a learner with inherited data permissions cannot validly perform the Reader-only negative test.
  • An access-denied result can come from networking, identity, or permissions. Hold other variables constant.
  • Activity log covers management actions; blob reads require storage data logging.
  • Budget alerts can lag and are not a hard cap. Deallocated compute can leave disks/IPs/storage charges.
  • MFA, scoped roles, dummy data, narrow ingress, and verified cleanup are part of the cloud exercise.

Support the six-hour learner

Use the first hour of a review to repair a blocking prerequisite only when necessary; otherwise keep the review short. Weeks 11, 13, and 24 can be heavier because of installation or access friction. At six hours weekly, remove optional exercises first and use Week 22 for catch-up. If core work still exceeds the budget, extend the calendar; do not omit basic validation to preserve an artificial six-month finish date.

Preparation for the instructor

  • Before Week 1: verify admin access, host backups, recovery key availability, and free resources.
  • Before Week 7: confirm evaluation downloads are available and the learner can activate them legitimately.
  • Before Week 11: inspect actual memory use; decide whether the 10 GB profile is practical. Validate the current Wazuh release and agent compatibility.
  • Before Week 13: verify the replay export/import path; native Windows monitoring is an optional resource upgrade.
  • Before Week 23: provide a sandbox, learner MFA identity, scoped access, budget, and a cleanup agreement.
  • Before public reuse: pilot the full course on a fresh machine; record actual timings, tool releases, ambiguous steps, and install failures.

Reuse and future publishing

The delivery uses static HTML and CSS: no accounts, payments, student database, or backend are required to read it. Host it later under your own domain if desired. Add student accounts or grading only when there is a concrete need. Keep a versioned course source, a changelog, and separate private instructor material if examination secrecy becomes important. In this first family edition, mentor answers are visible in the same bundle.

Do not label the course open source until you choose a license. For future redistribution, review the licenses of your original content and any bundled third-party material; this edition links to vendor documentation and does not redistribute OS ISOs or vendor logos. No paid-program or certification requirement is assumed. Treat this as edition 1.0 for instructor pilot validation, not a claim that every VM command has been executed on his laptop.
