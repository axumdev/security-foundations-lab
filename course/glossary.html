Diagnose by layer

  • 1. Scope: am I on the correct host/guest? Run hostname/whoami or Windows equivalents.
  • 2. Resources: enough RAM/disk? Inspect Task Manager, free -h, df -h.
  • 3. Link: correct virtual switch and adapter? Check Hyper-V Settings and ip -br link.
  • 4. Address/route: correct unique IP and mask? Check ip -br address, ip route, ipconfig /all.
  • 5. Name: can the correct DNS server resolve the required name? Test an IP separately from a name.
  • 6. Transport: is the service listening on the right address/port? Use ss or Get-NetTCPConnection.
  • 7. Policy: does a firewall or access rule intentionally deny the action? Test from the correct source identity/address.
  • 8. Service: running and valid config? Use systemctl status, nginx -t, sshd -t, or Event Viewer.
  • 9. Data pipeline: source event → collector → manager → index → dashboard. Inspect each boundary.
  • 10. Interpretation: correct timestamp, schema, expected behavior, and scope? An old alert is not evidence of a new test.

After 20–30 minutes without progress, stop changing settings. Save the exact error, last known working state, recent changes, versions, and tests already attempted. Ask the mentor a focused question with that evidence. This is professional escalation, not failure.
