WEEK 01 / FOUNDATIONS

Prepare your laptop.

By the end of this lesson, you’ll know whether your laptop can run the lab, have a place to save evidence, and be able to open Hyper-V Manager.

These steps use Hyper-V. If your computer does not have it, start the VirtualBox alternative here.

Work on the Windows host. That means your physical laptop. A guest is a computer running inside a VM. You won’t create a guest until Week 2.

Plan: About six hours across three sessions. Read the lab handbook before changing settings. Save your work before any restart.

Session 1 · Record and protect your host

1. Make a baseline record

On the laptop, open Start → Settings → System → About. Record the Windows edition, installed RAM, processor, and device name. Press Ctrl+Shift+Esc → Performance → CPU; record whether Virtualization says Enabled. Open File Explorer → This PC and record free space. Aim for at least 250 GB free before installing the course VMs. Close unnecessary applications during labs.

2. Protect the host

Back up personal work before changing virtualization settings. Apply Windows Update and restart. Open Windows Security and confirm antivirus and firewall are on. If device encryption or BitLocker is enabled, verify you can retrieve its recovery key before entering BIOS. Keep the key private. Use AC power and ventilation; save work and shut guests down cleanly before an expected power interruption.

Session 2 · Set up your notebook and check Hyper-V

3. Create the notebook

Open File Explorer. Create C:\CyberLab and subfolders ISOs, VMs, Evidence, Exports, and Private. Evidence is for sanitized learning results; Private is for anything containing passwords, keys, or sensitive configuration. Use a password manager for credentials. Do not publish Private or VM disks.

HOST • ordinary PowerShell
New-Item -ItemType Directory -Force -Path C:\CyberLab\ISOs,C:\CyberLab\VMs,C:\CyberLab\Evidence,C:\CyberLab\Exports,C:\CyberLab\Private
New-Item -ItemType Directory -Force -Path C:\CyberLab\Evidence\week01

For each week, create a matching Evidence\weekNN directory. Use the report template in this course. Write the purpose of each command before executing it. Afterward record expected versus actual results.

4. Check Hyper-V eligibility

Search Start for PowerShell, right-click Windows PowerShell → Run as administrator. The title should say Administrator. Run:

HOST • administrator PowerShell
systeminfo.exe
Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All

Windows 11 Pro supports Hyper-V; Home does not. Near the end of systeminfo, the virtualization requirements should be Yes, or it may say a hypervisor is already detected. If virtualization is disabled, open firmware setup using the instructions for your model (the key varies by manufacturer). Enable Intel VT-x or AMD-V, sometimes called SVM Mode. Menu wording varies. Do not change storage mode, boot mode, or unrelated firmware settings. If the setting is locked, get help from the laptop administrator.

Session 3 · Finish setup and verify your work

5. Enable Hyper-V

Save all work. Run the following once, then restart from the Start menu when prompted. Do not use it if Hyper-V is already enabled.

HOST • administrator PowerShell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

After restarting, search Start for Hyper-V Manager. Open it and select the local computer. If it is missing, check the Windows edition and feature state. Do not install multiple hypervisors to work around an unexplained error.

6. Establish the scope

Write: “My targets are the named course VMs and my mentor-provided cloud resource group only.” Never scan an employer, ISP, university, public address range, or household device. Use harmless test events and dummy data; this course does not require live malware. Agree on a regular review time with your mentor in both local time zones.

Explain in your own words: How is a checkpoint different from a backup? Which changes in this week affected the real laptop?

Hyper-V isn’t working
  • Hyper-V missing: confirm Pro edition, reboot, then inspect feature state. A firmware problem is a host problem; reinstalling guest operating systems will not fix it.
