Security platform extensions / Module 2

E2 · Build Elastic and ingest the common case

Prerequisites: E1 and core Week 14. Docker is introduced below; core Week 20 is helpful but not required.

Time: Three two-hour sessions: build, test, review. Extend the estimate if installation or a failed gate needs more time.

Power-on plan: ELASTIC01 only: 8 GB RAM, 4 vCPU, 80 GB disk. All Wazuh, Windows, Splunk, and Security Onion guests off.

Elasticsearch indexes and searches documents; Kibana provides a browser interface. Logstash will transform events in E3. You will keep authentication and Elasticsearch TLS enabled, learn mappings explicitly, and verify both successful ingestion and a denied unauthenticated request. The lab uses the self-managed Basic license, not a cloud trial.

1. Build and patch the Ubuntu guest

Follow Week 2’s installation screens with VM ELASTIC01, hostname elastic01, and the allocation above. Use Default Switch to patch Ubuntu and install the tools from E1. Record the installed OS and kernel. Install the Ubuntu-packaged Docker engine; do not add learner to the docker group, which grants broad guest control.

ELASTIC01 • Bash, update mode
sudo apt update
sudo apt upgrade
sudo apt install docker.io openssh-server curl nano jq unzip ca-certificates
sudo systemctl enable --now docker ssh
sudo docker version

2. Download one matching Elastic release

This edition follows the 9.5.3 images shown in the checked official documentation. Confirm all three tags exist and the release supports your platform before starting. Keep Elasticsearch, Kibana, and Logstash on the same patch version. If the mentor selects another version, change all three together and record it. Do not silently replace a version with latest.

ELASTIC01 • Bash, update mode
sudo docker pull docker.elastic.co/elasticsearch/elasticsearch:9.5.3
sudo docker pull docker.elastic.co/kibana/kibana:9.5.3
sudo docker pull docker.elastic.co/logstash/logstash:9.5.3
sudo docker image ls --digests

Images are software templates; containers are running instances. Record image digests. Downloads may exceed the session estimate. Never start Elasticsearch while still in update mode.

3. Set the review address and guest controls

Shut down, move the sole adapter to CyberLab-Review, boot in the console, and use Week 3’s netplan procedure with 10.78.0.40/24, no gateway or DNS. Confirm ip route has no default route. Allow SSH from the host, then enable the firewall:

ELASTIC01 • Bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 10.78.0.1 to any port 22 proto tcp
sudo ufw enable
sudo sysctl -w vm.max_map_count=1048576
printf "vm.max_map_count=1048576\n" | sudo tee /etc/sysctl.d/90-cyberlab-elastic.conf

vm.max_map_count permits the memory mappings used by the index engine. Docker can bypass expected ufw treatment for published ports; the loopback binds below are the actual service-exposure boundary.

4. Start Elasticsearch with security intact

ELASTIC01 • Bash
sudo docker network create elasticlab
sudo docker volume create elasticlab-data
sudo docker run -d -it --name es01 --network elasticlab -p 127.0.0.1:9200:9200 -m 3g -e discovery.type=single-node -e "ES_JAVA_OPTS=-Xms1g -Xmx1g" -v elasticlab-data:/usr/share/elasticsearch/data docker.elastic.co/elasticsearch/elasticsearch:9.5.3
sudo docker logs --tail 40 es01

Create the network/volume/container once. The volume retains index data across container stops; keep this container too because its generated security configuration lives there. Wait until the service is ready, then set a unique administrator password interactively:

ELASTIC01 • Bash
sudo docker exec -it es01 /usr/share/elasticsearch/bin/elasticsearch-reset-password -u elastic -i
sudo docker cp es01:/usr/share/elasticsearch/config/certs/http_ca.crt ./http_ca.crt
sudo chmod 644 http_ca.crt
curl --cacert ./http_ca.crt -u elastic https://localhost:9200
curl --cacert ./http_ca.crt -o /dev/null -w "%{http_code}\n" https://localhost:9200

curl -u elastic prompts for the password without putting it in command history. Expect authenticated cluster information and HTTP 401 without credentials. Do not disable security or use -k to make this pass. Store the password privately.

5. Enroll Kibana and open a narrow tunnel

ELASTIC01 • Bash
sudo docker run -d --name kib01 --network elasticlab -p 127.0.0.1:5601:5601 -m 2g docker.elastic.co/kibana/kibana:9.5.3
sudo docker exec -it es01 /usr/share/elasticsearch/bin/elasticsearch-create-enrollment-token -s kibana
sudo docker exec kib01 /usr/share/kibana/bin/kibana-verification-code

Wait for Kibana startup before requesting its verification code. From host PowerShell start the tunnel below, then browse http://localhost:5601. Enter the enrollment token and verification code if prompted. Sign in as elastic. Tokens expire; regenerate if needed. The browser HTTP hop is local and the remote hop is encrypted by SSH; this is not a deployed HTTPS Kibana endpoint.

HOST • PowerShell
ssh -N -L 5601:127.0.0.1:5601 learner@10.78.0.40

Keep the tunnel window open. In Kibana Stack Management → License Management confirm Basic. Do not click Start trial. Run Test-NetConnection 10.78.0.40 -Port 5601 on the host: direct access should fail, while the tunnel works.

6. Create an explicit mapping

Kibana → search for Dev Tools → Console. Submit this request. One shard and zero replicas are for a single-node disposable lab, not high availability.

Kibana • Dev Tools request
PUT lab-case-m01
{
  "settings": {"number_of_shards": 1, "number_of_replicas": 0},
  "mappings": {"properties": {
    "@timestamp": {"type": "date"},
    "event": {"properties": {"id": {"type": "keyword"}, "dataset": {"type": "keyword"}, "action": {"type": "keyword"}, "outcome": {"type": "keyword"}}},
    "labels": {"properties": {"case_id": {"type": "keyword"}, "synthetic": {"type": "keyword"}}},
    "source": {"properties": {"ip": {"type": "ip"}}},
    "destination": {"properties": {"ip": {"type": "ip"}}},
    "user": {"properties": {"name": {"type": "keyword"}}},
    "url": {"properties": {"path": {"type": "keyword"}}},
    "http": {"properties": {"response": {"properties": {"status_code": {"type": "integer"}}}}}
  }}
}

A mapping defines field types. An IP field supports address-aware operations; a keyword preserves exact values. Save the mapping in your notebook. Use the elastic administrator only for this private build; E6 designs a restricted analyst role.

7. Bulk-load and verify every item

Transfer case-m01 to ELASTIC01 with the E1 scp procedure and verify hashes. The bulk file contains alternating action/document lines, with stable IDs so repeating it replaces the same documents rather than doubling them.

ELASTIC01 • Bash
curl --cacert ~/http_ca.crt -u elastic -H "Content-Type: application/x-ndjson" --data-binary @/home/learner/case-m01/events.bulk.ndjson "https://localhost:9200/lab-case-m01/_bulk?refresh=true" > ~/case-m01/bulk-result.json
jq '{errors,items:(.items|length)}' ~/case-m01/bulk-result.json
curl --cacert ~/http_ca.crt -u elastic https://localhost:9200/lab-case-m01/_count

Expect errors:false, 16 item responses, and count:16. HTTP 200 alone does not prove each bulk operation succeeded. If errors:true, inspect the failing items before continuing.

8. Search, then close the session

Kibana → Stack Management → Data Views → Create data view. Name CASE-M01, pattern lab-case-m01, time field @timestamp. Open Discover, choose this view, and set an absolute interval covering 2026-09-01 09:59–10:03 UTC; account for Kibana’s displayed timezone or set dateFormat:tz to UTC in Advanced Settings. Run the KQL filter below.

Kibana • Discover KQL
event.dataset : "linux.auth" and event.outcome : "failure"

Expect six events. Inspect event.id, user.name, source.ip, and @timestamp. Search user.name:"nobody-in-this-case" and expect zero. Capture results, close the SSH tunnel, then sudo docker stop kib01 es01 and sudo poweroff. Do not remove the volume; E3 reuses it.

Pass this module

  • Authenticated success and unauthenticated 401
  • Basic license, mapped index, and all 16 successful bulk items
  • Six failed-login events and a zero-result negative query

Explain without the guide

  • Why can an HTTP 200 bulk response contain failed documents?
  • Why is zero replicas acceptable only for this disposable single-node exercise?

If something fails

Container exited: inspect docker logs and docker inspect state, free -h, and disk space. Use docker start es01 kib01 on later sessions, not duplicate docker run commands. Enrollment failure: wait for ES health and generate a fresh Kibana token. Empty Discover: check data view and fixed historical time range.
