Week 03 / Foundations

Build an isolated network and trace packets

6 hours core+ 0–6 hours practicePrerequisite: Week 02

An IP address identifies an interface; a subnet tells it which destinations are local. ARP maps local IPv4 addresses to Ethernet addresses. DNS maps names to addresses. A gateway forwards traffic beyond a subnet. TCP ports identify services. A private Hyper-V switch connects guests only; it does not connect the host or internet.

Power-on plan: UBU01 + newly installed UBU02, each 2 GB. Default Switch is used only for installation or updates; CyberLab-Private is the exercise network.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

1. Create the exercise switch

HOST • administrator PowerShell
New-VMSwitch -Name "CyberLab-Private" -SwitchType Private
Get-VMSwitch | Format-Table Name,SwitchType

Run New-VMSwitch only if that name does not already exist. Private is intentional. Do not substitute External, Internal, or Default Switch during isolated exercises. A NAT switch provides outbound access and is not isolation.

2. Install a second machine

Repeat Week 2’s VM wizard and Ubuntu installation with name UBU02, guest hostname ubu02, 2 GB RAM, 2 vCPU, and 40 GB disk. Use a fresh install, not a copy of an enrolled or running VM. Complete the same update and package steps. Shut down both guests. In each VM’s Settings → Network Adapter, choose CyberLab-Private. Each guest must have exactly one network adapter for these exercises.

3. Give UBU01 a fixed address

Start UBU01 and use the Hyper-V console. Run ip -br link and note the Ethernet interface, often eth0. The example below assumes eth0; substitute the observed interface name if different. Run ls /etc/netplan. Back up the existing YAML file(s) into ~/netplan-backup, then move the original YAML files out of /etc/netplan so only your new configuration controls the interface. These are guest commands.

Ubuntu guest • Bash
mkdir -p ~/netplan-backup
sudo mv /etc/netplan/*.yaml ~/netplan-backup/
sudo nano /etc/netplan/01-lab.yaml

Type this file with spaces, not tabs. nano: Ctrl+O, Enter saves; Ctrl+X exits.

UBU01 • /etc/netplan/01-lab.yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      dhcp6: false
      accept-ra: false
      addresses: [10.77.0.11/24]
Ubuntu guest • Bash
sudo chmod 600 /etc/netplan/01-lab.yaml
sudo netplan generate
sudo netplan try

Confirm within the displayed timeout after checking the console still works. Run ip -br address and ip route. Expect 10.77.0.11/24 and a connected 10.77.0.0/24 route, with no default route. No gateway or DNS server is configured on this private segment.

4. Configure UBU02 and prove isolation

Repeat the previous step inside UBU02, using 10.77.0.12/24. Then on UBU02 run:

Ubuntu guest • Bash
ping -c 3 10.77.0.11
ip neigh
ip route
ping -c 1 -W 2 1.1.1.1

The peer ping should work. The internet ping should fail with network unreachable or no reply; also confirm no default route and the Private switch on the host. A failed ping alone is not sufficient proof of isolation. Document both switch settings and routing tables.

5. Watch a real conversation

On UBU01 start a packet capture; leave it running. On UBU02 run the ping and HTTP request below. Then return to UBU01 and press Ctrl+C.

UBU01 • Bash; replace eth0 if needed
sudo tcpdump -ni eth0 -w /tmp/week03.pcap "arp or icmp or tcp port 80"
UBU02 • Bash
ping -c 3 10.77.0.11
curl -I http://10.77.0.11
UBU01 • Bash
sudo tcpdump -nn -r /tmp/week03.pcap | head -40

If nginx is stopped, start it with sudo systemctl start nginx and repeat. Identify source/destination IPs, ports, and TCP SYN/SYN-ACK/ACK. The capture sees traffic involving UBU01, not automatically all traffic on the virtual switch.

6. Understand update mode

To update a Linux VM later: shut it down, connect its only adapter to Default Switch, and in its console change the netplan interface block to dhcp4: true, removing addresses. Apply with netplan try, then check IP, default route, DNS resolution, and apt update. After updates, shut down, reconnect CyberLab-Private, restore that VM’s static address file, apply and verify isolation again. Never take deliberately vulnerable services into update mode while they are listening.

Pass this week

  • Address plan and diagram
  • Peer connectivity plus three isolation checks
  • PCAP with an annotated TCP conversation

Explain without the guide

  • Why does peer HTTP work without DNS?
  • Why is Default Switch unsuitable for the isolated test network?

If something fails

Peer timeout: check both switch names, unique addresses, /24 masks, and guest firewall. Internet working in exercise mode: stop the exercise and inspect additional adapters, gateways, and host routing. Incorrect YAML: netplan generate identifies the line.

Optional practice · 0–6 extra hours

Calculate network, broadcast, and usable host addresses for 10.77.0.0/24. Inspect packet capture text for Ethernet versus IP addressing.
