Week 17 / Assurance

Assess exposure and prioritize remediation

6 hours core+ 0–6 hours practicePrerequisite: Week 16

An open port is exposure, not automatically a vulnerability. A package version alone may mislead when distributions backport fixes. Vulnerability management combines asset importance, reachability, evidence, remediation, and retesting. A hardening score is a guide, not a complete risk measure.

Power-on plan: UBU01 + UBU02, 4 GB total. No scanning outside 10.77.0.11. Wazuh off.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

Expanded track: See the six security-platform labs and schedule for Elastic, Splunk, and Security Onion. Budget these hours separately from the core; complete their comparison report for the final review.

1. Install a local configuration auditor

In UBU01 update mode install the open-source Lynis package and record its version. Return to private mode before scanning. Stop Suricata’s foreground process if still running.

UBU01 • Bash, update mode
sudo apt install lynis
lynis show version

2. Inventory before scanning

UBU01 • Bash
hostnamectl
sudo ss -lntup
dpkg-query -W nginx openssh-server openssl
sudo ufw status verbose

Create an asset row: owner learner, purpose lab web service, data dummy, criticality low, private-only exposure, patch date, and installed versions.

3. Perform a bounded service scan

UBU02 • Bash
mkdir -p ~/lab/week17
nmap -sT -sV -Pn -p 22,80,443 10.77.0.11 -oA ~/lab/week17/ubu01-services

The scan is limited to three known ports on the owned guest. Compare results with ss and firewall rules. Filtered, closed, and open mean different things. The output is evidence of observed service behavior, not a proven CVE.

4. Audit configuration

UBU01 • Bash
sudo lynis audit system
sudo cp /var/log/lynis-report.dat /tmp/lynis-before.dat
sudo chmod 600 /tmp/lynis-before.dat

Read warnings/suggestions and choose two relevant findings, not the entire list. For each, state impact, evidence, whether it applies to this lab, a change, and a rollback. Never apply a hardening script blindly.

5. Remediate an unnecessary service

Treat nginx as unnecessary for this one exercise. Save baseline output, then stop and disable it. Do not uninstall it; later weeks reuse it.

UBU01 • Bash
sudo systemctl disable --now nginx
sudo ss -lntp

Repeat the three-port scan from UBU02. Ports 80/443 should no longer be open. Restore nginx with sudo systemctl enable --now nginx and verify both services again. This reversible demonstration proves exposure reduction without asserting that nginx itself was vulnerable.

6. Write the remediation report

Document three items: the unnecessary-service exercise, one validated Lynis finding, and one finding you defer with a reason. If you research a CVE, use the distribution security advisory for the installed package release and record fix status. Separate confirmed vulnerability, configuration weakness, and unverified scanner suggestion.

Pass this week

  • Service inventory matched to scan
  • Before/after/recovery exposure test
  • Three-item prioritized remediation register

Explain without the guide

  • Why might a banner version produce a false positive?
  • Why is remediation incomplete before retesting?

If something fails

Scan and ss disagree: check bound address, firewall, correct VM/IP, and whether you scanned before or after the change. A failed internet update in private mode is expected; use the defined update procedure.

Optional practice · 0–6 extra hours

Read an Ubuntu security notice for a package you installed, and explain backported fixes. Optional Wazuh vulnerability assessment needs current feeds and a separately documented online session.
