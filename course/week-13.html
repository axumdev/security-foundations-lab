Week 13 / Detection

Capture Windows process telemetry

6 hours core+ 0–6 hours practicePrerequisite: Week 12

Sysmon adds detailed system events. Process creation records can connect an image, command line, parent, user, and timestamp. This week separates event capture from analysis to fit 16 GB: exported JSON is a replay dataset, not a live Windows agent connection.

Power-on plan: Stage A: WIN01 4 GB, optionally DC01 4 GB for domain logon. Stage B: WAZUH01 8 GB + UBU01 2 GB. Never all together.

For dashboard access and file transfers, use the complete temporary management procedure in the lab handbook, including the explicit host key path and cleanup checks.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

1. Install Sysmon on WIN01

Use the official Sysmon archive downloaded in Week 7. In administrator PowerShell change to C:\Tools\Sysmon. Inspect the digital signature with Get-AuthenticodeSignature .\Sysmon64.exe and require a valid Microsoft signature. Then install the basic configuration:

WIN01 • administrator PowerShell
.\Sysmon64.exe -accepteula -i
Get-Service Sysmon64

Read the license before accepting it. Default Sysmon captures process creation; do not assume all optional event types such as network connections are enabled. Keep the default configuration for this exercise.

2. Produce a known event

WIN01 • administrator PowerShell
New-Item -ItemType Directory -Force C:\LabEvidence
cmd.exe /c "echo CYBERLAB-W13"
Get-WinEvent -FilterHashtable @{LogName="Microsoft-Windows-Sysmon/Operational";Id=1} -MaxEvents 20 | Format-List TimeCreated,Id,Message

Open Event Viewer → Applications and Services Logs → Microsoft → Windows → Sysmon → Operational. Find cmd.exe with CYBERLAB-W13, its parent process and user. This is a benign command, not malware.

3. Export raw and normalized evidence

WIN01 • administrator PowerShell
wevtutil epl Microsoft-Windows-Sysmon/Operational C:\LabEvidence\sysmon.evtx
$rows = Get-WinEvent -FilterHashtable @{LogName="Microsoft-Windows-Sysmon/Operational";Id=1} -MaxEvents 30 | ForEach-Object {
  [xml]$eventXml = $_.ToXml()
  $fields = @{}
  foreach ($item in $eventXml.Event.EventData.Data) { $fields[$item.Name] = $item.InnerText }
  [ordered]@{lab_source="windows_replay";event_id=1;event_time=$_.TimeCreated.ToUniversalTime().ToString("o");image=$fields["Image"];command_line=$fields["CommandLine"];parent_image=$fields["ParentImage"];user=$fields["User"]} | ConvertTo-Json -Compress
}
[IO.File]::WriteAllLines("C:\LabEvidence\windows-events.json", [string[]]$rows, [Text.UTF8Encoding]::new($false))
Get-FileHash C:\LabEvidence\sysmon.evtx -Algorithm SHA256

Keep raw EVTX separately from derived JSON. The JSON schema is this course’s schema and does not match Wazuh’s native Windows event-channel schema. Inspect and redact account identifiers before public sharing; never collect real passwords in command lines.

4. Retrieve the JSON without a network bridge

HOST • administrator PowerShell
$guestCred = Get-Credential -Message "WIN01 local Administrator credential"
$eventText = Invoke-Command -VMName WIN01 -Credential $guestCred -ScriptBlock { Get-Content C:\LabEvidence\windows-events.json -Raw }
[IO.File]::WriteAllText("C:\CyberLab\Private\windows-events.json", [string]$eventText, [Text.UTF8Encoding]::new($false))

PowerShell Direct uses Hyper-V guest integration. Enter WIN01\Administrator and the local password, so DC01 is not required for this step. Check Get-Content on the host produces one JSON object per line. Keep the original EVTX in the VM or export it using a binary-safe transfer, not this text method. Shut WIN01/DC01 down.

5. Stage the replay for next week

Start UBU01 and WAZUH01. Use Week 11’s temporary management connection to UBU01, and from the host use scp -i "$env:USERPROFILE\.ssh\cyberlab_host" C:\CyberLab\Private\windows-events.json learner@UBU01_DEFAULT_IP:~/windows-events.json, replacing the address. From UBU01 copy to WAZUH01 using scp ~/windows-events.json learner@10.77.0.30:~/windows-events.json; verify its SSH fingerprint in the manager console. WAZUH01 uses its own learner password unless you configure a key. Remove UBU01’s temporary adapter afterward. Keep the replay file for Week 14.

6. Compare native collection with replay

Write what this experiment proves: Sysmon produced a process event and you preserved selected fields. It does not prove a live Windows agent, continuous coverage, delivery latency, or native Wazuh Windows detections. Optional with 32 GB or a mentor-hosted manager: deploy a matching Windows Wazuh agent from Agents management → Deploy new agent, set manager 10.77.0.30 on the private network, add a localfile eventchannel block for Microsoft-Windows-Sysmon/Operational, restart WazuhSvc, and verify the same marker in native events.

Pass this week

  • Raw Sysmon event and parent/child explanation
  • Hashed EVTX plus normalized JSON
  • Explicit live-versus-replay limitations

Explain without the guide

  • Why preserve raw evidence before transforming it?
  • Does a process event tell you whether the action was authorized?

If something fails

PowerShell Direct failure: confirm WIN01 is running, use host administrator PowerShell and a valid local guest credential. Sysmon event absent: check channel/service, run a new cmd marker, and adjust time range. Do not claim network event coverage from defaults.

Optional practice · 0–6 extra hours

With additional RAM, implement the optional native Windows agent and compare its schema to the replay. Keep this outside the 16 GB core requirement.
