Lab operating handbook

You are building a small environment in stages.

  1. Keep this page open beside the weekly instructions.
  2. Do not start all VMs simply because they exist.

The host is your physical computer; every other named machine is a guest.

What this course assumes

  • Windows 11 Pro, full local administrator access, and permission to change virtualization settings. Week 1 verifies these assumptions; stop host setup if they are false.
  • 16 GB RAM, an SSD with at least 250 GB free for the initial plan, and functioning cooling. Available disk and memory—not the listing alone—decide what can run.
  • English reading, good internet for downloads, 6 hours minimum weekly, with extra hours for practice. No previous Linux, Windows administration, or cloud experience is assumed.
  • Use an authorized Azure sandbox, a dedicated personal learning subscription, or the local alternative in Week 23. No paid training subscription is required.
  • Plan time for a self-review or an optional mentor review.

Learning solo?

When a lesson calls for mentor review, use these checks yourself.

Record a short teach-back or write your explanation from memory.

  • Predict what should happen before running the test.
  • Save the observed result, including a denied case when the lab calls for it.
  • Explain any mismatch and repeat the test after your fix.
  • Record how to undo the change and whether the lab is safe to leave running.
  • Write your case conclusions before opening mentor-answer-key.json. Teachers can hand out the evidence files separately without the key.

Power profiles for 16 GB

  • Linux: UBU01 + UBU02 = 4 GB guest RAM.
  • Identity: DC01 + WIN01 = 8 GB. Linux and Wazuh off.
  • Monitoring: WAZUH01 + UBU01 = 10 GB. All others off.
  • Windows capture: WIN01 alone or with DC01, then shut them down before Wazuh analysis.
  • Cloud: host browser only. Local VMs off.
Measure actual host memory in Task Manager. Fixed guest memory plus host/browser use can still cause paging on 16 GB. If the monitoring profile is unstable, stop and arrange more RAM or a mentor-provided server; do not lower Wazuh below the documented allocation and call it equivalent. A 32 GB upgrade would be helpful but is not assumed. Verify compatible modules in your computer manufacturer’s documentation before purchasing.

Every session: start, test, close

  • Read the week’s prerequisites and power-on plan. Record date/time, VM names, and the one objective for the session.
  • Check host free memory/disk. Start only the required guests. Verify hostname and IP before copying commands.
  • Before a change, save the specific configuration file and note how to undo it. Use a named checkpoint only where appropriate.
  • State the expected result, run one step, inspect actual output, and save sanitized evidence. Stop if a command fails rather than pasting the rest of a block.
  • For tests, verify Private switch, one adapter, and no default route. For temporary management, verify no training container or simulator is running.
  • At the end, stop foreground tools/containers, remove temporary rules/adapters, record unfinished work, and shut guests down through their OS. Close cloud resources as instructed.

Command and editor survival guide

  • Each dark command block names its execution location. HOST means your physical computer; UBU01 and other names mean that guest. PowerShell and Bash syntax are not interchangeable.
  • REPLACE_ tokens are instructions to substitute an actual observed value. Never paste them unchanged. Angle-bracket placeholders in vendor documentation work similarly.
  • In nano: Ctrl+O → Enter saves; Ctrl+X exits; Ctrl+W searches. Use spaces in YAML. XML opening/closing tags must match.
  • Ctrl+C stops a foreground command. q exits less, man, and many pagers. Do not close the whole VM merely to leave a terminal tool.
  • Linux paths are case-sensitive. ~/ means the current user’s home. 127.0.0.1 means this machine, so it refers to different machines in host and guest terminals.
  • sudo elevates one Linux command. Windows administrator PowerShell is opened using Run as administrator. Never make a habit of pasting unreviewed internet scripts.

Backup and checkpoint rules

  • A checkpoint is short-term rollback inside a VM disk chain. It is not a backup, and reverting may lose collected evidence or enrolled-agent state.
  • Keep a clean baseline and at most a few recent change checkpoints. Delete through Hyper-V Manager and wait for merging; never manually delete AVHDX files.
  • Before AD exercises, prefer an orderly shutdown and coordinated export of both domain machines. Do not randomly revert one domain member or controller to repair an identity problem.
  • Course evidence belongs outside guest disks too. Keep private originals separate from sanitized portfolio copies. Off-device backups need separate storage that the laptop does not supply by itself.

Version policy and downloads

Baseline: Windows 11 Pro host, Ubuntu Server 24.04 LTS guests, Windows Server 2025 Evaluation Desktop Experience, Wazuh 4.14 family (4.14.7 packages observed during authoring), OISF stable Suricata (8.x documentation), Ubuntu-packaged Lynis/restic/Docker, official nginx image. Exact patch versions can change.

  1. Save the real installed versions and consult linked official documentation before each installation.
  2. Do not assume a newer major release is interchangeable.

Stage downloads just before the relevant week rather than filling the SSD on day one.

Budget roughly several GB per OS ISO, additional packages/images, and repeated security updates; actual downloads vary. Retain verified installers where space permits. Windows evaluations have time limits and activation requirements: install in Week 7/8, record expiration, and never work around licensing by changing the clock. All security stacks here are open-source tools except explicitly named Windows/Sysmon/Azure components; free evaluation is not open-source licensing.

When to stop and ask the mentor

  • The target might be the real host, another person’s system, or a cloud group outside scope.
  • The expected isolated network has an unexplained route or adapter.
  • A command asks to delete, format, or overwrite data you have not identified.
  • A tool needs more resources than this laptop can provide.
  • The actual software release or schema differs enough that tests fail. Preserve the error and version; do not improvise a chain of unverified fixes.
