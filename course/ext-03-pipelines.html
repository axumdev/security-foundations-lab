Security platform extensions / Module 3

E3 · Engineer a pipeline, detection, and retention policy

Prerequisites: E2; keep ELASTIC01 and its containers/data volume.

Time: Three two-hour sessions: build, test, review. Extend the estimate if installation or a failed gate needs more time.

Power-on plan: ELASTIC01 only, 8 GB. Elasticsearch 3 GB container limit + Kibana 2 GB + temporary Logstash 1 GB; monitor host/guest pressure.

Log transport, parsing, field normalization, detection, and retention are separate engineering jobs. You will transform a differently shaped source into the same event model, reject a bad timestamp, and demonstrate why pipeline failures must be visible.

1. Resume and inspect source differences

ELASTIC01 • Bash
sudo docker start es01 kib01
head -1 ~/case-m01/auth-input.ndjson
head -1 ~/case-m01/events.ndjson
mkdir -p ~/elastic-pipeline

Reopen the SSH tunnel from E2. auth-input has flat source fields such as client_ip and result; events.ndjson has normalized nested fields. There are eight source authentication records. Do not ingest them into the existing 16-event index or your comparison counts will be misleading.

2. Build the Logstash transformation

Create ~/elastic-pipeline/normalize.conf with nano. This first pipeline writes to standard output only; it deliberately separates parsing from indexing. Docker will use stdin for these line-delimited events.

ELASTIC01 • normalize.conf
input { stdin { codec => json } }
filter {
  mutate {
    rename => {
      "event_id" => "[event][id]"
      "client_ip" => "[source][ip]"
      "username" => "[user][name]"
      "result" => "[event][outcome]"
      "case_id" => "[labels][case_id]"
    }
    add_field => {
      "[event][dataset]" => "linux.auth"
      "[event][action]" => "ssh_login"
      "[labels][synthetic]" => "true"
    }
  }
  date { match => ["event_time", "ISO8601"] target => "@timestamp" }
  mutate { remove_field => ["event_time", "@version", "host"] }
}
output { stdout { codec => json_lines } }

Do not put a drop filter on parse failures. The date filter adds _dateparsefailure when parsing fails; those records must remain observable.

3. Validate and run the pipeline

ELASTIC01 • Bash
sudo docker run --rm --network none -m 1g -e "LS_JAVA_OPTS=-Xms512m -Xmx512m" -v "$HOME/elastic-pipeline/normalize.conf:/usr/share/logstash/pipeline/normalize.conf:ro" docker.elastic.co/logstash/logstash:9.5.3 -f /usr/share/logstash/pipeline/normalize.conf --config.test_and_exit
sudo docker run --rm -i --network none -m 1g -e "LS_JAVA_OPTS=-Xms512m -Xmx512m" -v "$HOME/elastic-pipeline/normalize.conf:/usr/share/logstash/pipeline/normalize.conf:ro" docker.elastic.co/logstash/logstash:9.5.3 -f /usr/share/logstash/pipeline/normalize.conf --log.level error --pipeline.workers 1 < ~/case-m01/auth-input.ndjson > ~/elastic-pipeline/output.txt

Logstash may emit startup text even with error logging. Extract only valid JSON event lines with the small script below; require exactly eight valid records and inspect any other lines. No network is needed because this stage only transforms files.

ELASTIC01 • save as ~/elastic-pipeline/prepare.py, then run python3 ~/elastic-pipeline/prepare.py
import json
from pathlib import Path
p = Path.home() / "elastic-pipeline"
rows = []
for line in (p / "output.txt").read_text().splitlines():
    try:
        e = json.loads(line)
    except json.JSONDecodeError:
        continue
    if isinstance(e, dict) and isinstance(e.get("event"), dict) and e["event"].get("id"):
        rows.append(e)
assert len(rows) == 8, f"Expected 8 events, got {len(rows)}"
assert all("_dateparsefailure" not in e.get("tags", []) for e in rows)
with (p / "auth.bulk.ndjson").open("w") as out:
    for e in rows:
        out.write(json.dumps({"index": {"_id": e["event"]["id"]}}) + "\n")
        out.write(json.dumps(e) + "\n")
print("Prepared", len(rows), "normalized events")

4. Send validated output to a separate index

In Dev Tools create lab-auth-m01 using the same mapping request as E2, changing only the index name. Then submit the generated bulk file with curl:

ELASTIC01 • Bash
curl --cacert ~/http_ca.crt -u elastic -H "Content-Type: application/x-ndjson" --data-binary @/home/learner/elastic-pipeline/auth.bulk.ndjson "https://localhost:9200/lab-auth-m01/_bulk?refresh=true" > ~/elastic-pipeline/bulk-result.json
jq '{errors,items:(.items|length)}' ~/elastic-pipeline/bulk-result.json

Require eight successful items. Create a separate data view lab-auth-m01 with @timestamp. Compare IDs, original times, outcomes, and source IPs to the eight authentication records in lab-case-m01. This is a staged file pipeline; a continuously running collector/output is a later extension, not something this test proves.

5. Break the timestamp deliberately

Run the same Logstash command from step 3 with auth-bad.ndjson as input and output-bad.txt as destination. Inspect its emitted JSON and tags. Expect _dateparsefailure. Its fallback @timestamp is processing time, so a search in the historical case window may miss it. Keep that result outside your clean comparison indexes and record how you would quarantine and alert on it.

Then in Dev Tools submit POST lab-auth-m01/_doc/bad-ip with body {"source":{"ip":"not-an-ip"}}. Expect a mapping-related HTTP 400. Verify _count remains eight. Delete is unnecessary because the invalid document should never have been indexed.

6. Define and replay a detection honestly

Kibana → Security → Rules/Detection rules → Create new rule → Threshold. Source index: lab-case-m01. KQL: event.dataset:"linux.auth" and event.outcome:"failure". Group by source.ip and user.name; threshold 5. Name LAB-M01 repeated failures. Interval 1 minute; additional look-back 2 minutes. Keep external actions off and save enabled. Inspect the execution log for a successful run before generating events.

Original evidence is historical. Save the following script as ~/case-m01/replay.py with nano. It creates a separate, labeled replay: six current-time failures from .12 and four from .88, preserving the original timestamp in event.created. It never edits the evidence files.

ELASTIC01 • Python file ~/case-m01/replay.py
import json
from datetime import datetime, timezone
from pathlib import Path
base = Path.home() / "case-m01"
originals = [json.loads(s) for s in (base / "events.ndjson").read_text().splitlines()]
failures = [e for e in originals if e["event"].get("outcome") == "failure" and e["event"]["dataset"] == "linux.auth"]
now = datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")
with (base / "replay.bulk.ndjson").open("w") as out:
    for n in range(10):
        e = json.loads(json.dumps(failures[n % 6]))
        identity = f"REPLAY-M01-{n+1:02}"
        e["event"]["created"] = e["@timestamp"]
        e["@timestamp"] = now
        e["event"]["id"] = identity
        e["labels"]["case_id"] = "M01-REPLAY" if n < 6 else "M01-NEGATIVE"
        e["source"]["ip"] = "10.77.0.12" if n < 6 else "10.77.0.88"
        out.write(json.dumps({"index": {"_id": identity}}) + "\n")
        out.write(json.dumps(e) + "\n")
print("Prepared six positive and four negative events at", now)
ELASTIC01 • Bash
python3 ~/case-m01/replay.py
curl --cacert ~/http_ca.crt -u elastic -H "Content-Type: application/x-ndjson" --data-binary @/home/learner/case-m01/replay.bulk.ndjson "https://localhost:9200/lab-case-m01/_bulk?refresh=true" > ~/case-m01/replay-result.json
jq '{errors,items:(.items|length)}' ~/case-m01/replay-result.json

Require errors:false and ten items. After at least two successful scheduled executions, open Alerts and filter to this rule and the current time. Expect a threshold alert for .12/trainee01, and none for .88/trainee01. Inspect source events to confirm six versus four; absence of an alert is meaningful only if the rule ran successfully. Capture evidence and disable the rule. If the time window elapsed during troubleshooting, rerun the script and bulk load; stable IDs replace only the ten replay documents. Scope every original-case query to labels.case_id:"CASE-M01". Record that this proves scheduled detection of a replay, not live collection or a historical alert.

7. Create a scoped retention policy

In Dev Tools submit these requests. The policy starts a seven-day delete phase from index lifecycle age; it is not seven days after each event timestamp. The template matches future lab-expiring-* indexes only. It does not apply to Wazuh or the comparison indexes.

Kibana • Dev Tools, send each request separately
PUT _ilm/policy/lab-seven-day
{"policy":{"phases":{"delete":{"min_age":"7d","actions":{"delete":{}}}}}}

PUT _index_template/lab-expiring-template
{"index_patterns":["lab-expiring-*"],"template":{"settings":{"index.lifecycle.name":"lab-seven-day","number_of_shards":1,"number_of_replicas":0}}}

PUT lab-expiring-check

GET lab-expiring-check/_ilm/explain

Verify managed:true and the expected policy. Do not claim you observed seven-day deletion today. After recording evidence, delete only lab-expiring-check, the lab-expiring-template template, and lab-seven-day policy through their corresponding DELETE requests. Record a backup/export requirement before any real retention change.

8. Close and assess

Save configuration, positive/negative counts, the malformed-date result, mapping rejection, rule execution evidence, and retention explanation. Stop kib01 and es01, close the SSH tunnel, and shut down ELASTIC01. Do not run it alongside Splunk in E4.

Pass this module

  • Eight transformed events matching the canonical IDs/times
  • Observable malformed-date and invalid-IP failures
  • Threshold positive/negative replay plus scoped retention policy

Explain without the guide

  • Why can a parsing failure become a misleading time-window problem?
  • How is an index-age retention policy different from per-event expiration?

If something fails

Logstash does not exit: verify redirected input reaches EOF; inspect output before interrupting. Missing JSON: check the bind-mounted filename and pipeline syntax. Rule does not fire: check enabled state, license-supported rule type, execution errors, source index, data timestamps, and group threshold. Never change the original fixture to hide a time problem.
