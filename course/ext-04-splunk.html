Security platform extensions / Module 4

E4 · Investigate with Splunk and understand Free limits

Prerequisites: E1–E3. Save Elastic evidence before powering ELASTIC01 off.

Time: Three two-hour sessions: build, test, review. Extend the estimate if installation or a failed gate needs more time.

Power-on plan: SPLUNK01 only: Ubuntu Server, 6 GB RAM, 2 vCPU, 60 GB disk; review address 10.78.0.41. All other SIEM guests off.

Use Splunk Enterprise Search & Reporting to investigate the same 16 records. Splunk is proprietary. Its Free license is a constrained learning option, not a free copy of Splunk Enterprise Security. You will document the license actually installed and avoid claiming unavailable features.

1. Install the guest and obtain the official package

Create SPLUNK01 using Week 2, allocating the profile above. Patch Ubuntu on Default Switch and install openssh-server, nano, curl, jq, unzip, and ca-certificates. From the official Splunk Enterprise download page choose a supported Linux x86-64 .tgz package; an account and license acceptance may be required. Check the current supported OS matrix before downloading; this course uses Ubuntu 24.04. Record version, filename, download date, and the official checksum. Do not download Enterprise Security, a Universal Forwarder, or a third-party repack.

After patching, move the sole NIC to CyberLab-Review and configure 10.78.0.41/24 without gateway/DNS using E1. Enable ufw with inbound SSH allowed only from 10.78.0.1. Transfer the verified package from the host with scp and name the guest copy ~/splunk.tgz. Verify its SHA-256 again. Keep the original versioned filename in your manifest.

2. Extract and configure a non-root service account

SPLUNK01 • Bash; fresh installation only
sudo useradd --system --create-home --user-group splunk
sudo tar -xzf ~/splunk.tgz -C /opt
sudo chown -R splunk:splunk /opt/splunk
sudo -u splunk mkdir -p /opt/splunk/etc/system/local
sudo -u splunk nano /opt/splunk/etc/system/local/web.conf

Enter the following web.conf. Edit only the local directory, never system/default. The loopback binding keeps the web interface behind the SSH tunnel even after Free removes authentication.

SPLUNK01 • web.conf
[settings]
httpport = 8000
server.socket_host = 127.0.0.1

Save and exit. Start as the splunk account, read and accept the license when prompted, and choose a unique administrator credential. Do not put its password on the command line.

SPLUNK01 • Bash
sudo -u splunk /opt/splunk/bin/splunk start
sudo ss -lntp
sudo ufw status verbose

Require TCP 8000 on 127.0.0.1 only. The management port 8089 may listen more broadly; guest ufw must block remote access to it. Do not enable receiving on 9997 or open other guest ports for this file-only lab.

3. Connect and identify the license

HOST • PowerShell
ssh -N -L 8000:127.0.0.1:8000 learner@10.78.0.41

Keep the tunnel open and browse http://localhost:8000. Sign in and choose Search & Reporting. Settings → Licensing: record the license, expiry, and daily allowance. A new installation normally begins with a 60-day Enterprise trial limited to 500 MB/day. Free also permits 500 MB/day but removes authentication, roles, and alerting. Complete the next searches on either license; the optional trial alert is separate. Do not enable a paid/cloud trial just to complete this module.

HOST • a second PowerShell window
Test-NetConnection 10.78.0.41 -Port 8000
Test-NetConnection 10.78.0.41 -Port 8089

Both direct tests must fail while the local browser works. If either succeeds, stop Splunk from the console, correct loopback/firewall settings, then repeat.

4. Upload once and validate timestamps

Settings → Indexes → New Index: name lab_m01, use event data, and save. Settings → Add Data → Upload: choose the host working copy of events.ndjson. At Set Source Type select the built-in _json type. Preview must show 16 distinct events; expand one to confirm the nested structure. In timestamp options use the event field @timestamp; where advanced parsing fields are shown use TIME_PREFIX "@timestamp"\s*:\s*" and TIME_FORMAT %Y-%m-%dT%H:%M:%SZ with MAX_TIMESTAMP_LOOKAHEAD 20. Verify the preview resolves to September 1, 2026, 10:00 UTC, not today. Stop before Submit if preview time or event boundaries are wrong.

Input Settings: choose index lab_m01; give the source a recognizable CASE-M01 name and submit once. This upload is one-time indexing, not continuous forwarding. In Search & Reporting use All time initially; run:

Splunk • SPL
index=lab_m01
| spath path=event.id output=case_event_id
| stats count dc(case_event_id) AS unique_ids min(_time) AS first max(_time) AS last
| convert ctime(first) ctime(last)

Require count=16 and unique_ids=16. Check both boundary times against the fixture answer key, accounting for display timezone. Duplicate upload is a failed ingestion check: do not use dedup to hide it. For a mistaken first attempt, create a fresh index lab_m01_retry, repeat once correctly, and substitute that exact index in every query. Retain the explanation; do not issue broad delete commands.

5. Translate the investigation into SPL

Splunk • failed-login SPL
index=lab_m01
| spath path=labels.case_id output=case_id
| spath path=event.dataset output=dataset
| spath path=event.outcome output=outcome
| spath path=source.ip output=client
| spath path=user.name output=username
| search case_id="CASE-M01" dataset="linux.auth" outcome="failure"
| stats count BY client username

Expect trainee01 at 10.77.0.12 with six failures. Use the fixed case time range from E1. Change outcome to success and inspect the two successes; decide whether success alone proves compromise.

Splunk • HTTP SPL
index=lab_m01
| spath path=event.dataset output=dataset
| spath path=url.path output=path
| spath path=http.response.status_code output=status
| search dataset="web.access"
| table _time path status
| sort _time
Splunk • process-marker SPL
index=lab_m01
| spath path=process.command_line output=command_line
| search command_line="*CYBERLAB-M01*"
| table _time command_line

Expect four web events (two 404s) and one marker. For the negative test use index=lab_m01 | spath path=user.name output=username | search username="nobody-in-this-case" and require zero. Save the three searches as reports where the installed license permits; otherwise export query text and CSV results to your evidence folder.

6. Test the license boundary

If using the Enterprise trial, optionally save the failed-login aggregation as an alert that triggers when count ≥ 5, with all external actions off. Historical data requires an explicit historical search interval or current-time replay; do not claim a scheduled alert was tested by merely saving it. The required Free-path outcome is the saved query/result, not an alert.

After exporting evidence, go to Settings → Licensing → Change license group and select Free license if available, acknowledge the listed losses, and restart when requested. Reopen the SSH tunnel/browser. Record the actual license and confirm that there is no ordinary user-login barrier and alerting is unavailable. If this release/account does not offer Free, stop at the trial and document its expiry; do not fabricate a free entitlement or bypass licensing. The comparison must then say “trial tested; Free limits documented.”

7. Write the operations note and shut down

Record index size, ingestion allowance used, installed version, time parsing settings, three SPL queries, zero-result check, and the direct-port failures. Explain why a service without authentication cannot be offered as a shared teaching server. Close the tunnel, stop Splunk, and shut down the guest.

SPLUNK01 • Bash
sudo -u splunk /opt/splunk/bin/splunk stop
sudo poweroff

On a later session use sudo -u splunk /opt/splunk/bin/splunk start; do not re-extract the installation or re-upload evidence.

Pass this module

  • Six failures, four HTTP rows, one marker, and zero non-existent-user matches
  • 16 unique indexed records with original event times
  • Actual license and verified interface exposure documented

Explain without the guide

  • What is lost when the Enterprise trial becomes Free?
  • Why does querying a file upload not validate endpoint forwarding?

If something fails

No browser: check service status, loopback listener, SSH tunnel, and port conflicts on the host. No events: begin with All time and the exact index, then inspect timestamp parsing. A blank historical view is not proof that upload failed. Wrong license: use the installed capabilities honestly and record the constraint.
