Week 18 / Response

Contain, preserve, and recover an incident

6 hours core+ 0–6 hours practicePrerequisite: Week 17

Incident response protects operations while preserving enough evidence to make decisions. Containment limits impact; eradication removes the cause; recovery restores trusted service. A lab simulation can teach this workflow without executing malware or stealing credentials.

Power-on plan: Stage A UBU01 + UBU02. Stage B WAZUH01 + UBU01 if reviewing FIM. Never exceed the 10 GB guest budget.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

Expanded track: See the six security-platform labs and schedule for Elastic, Splunk, and Security Onion. Budget these hours separately from the core; complete their comparison report for the final review.

1. Prepare the case and baseline

Create case LAB-018 and a timeline. Verify /srv/labshare/case.txt contains only dummy data. Save a copy and hash in ~/lab/week18 before any simulation. Note current nginx and firewall state.

UBU01 • Bash
mkdir -p ~/lab/week18
sudo cp -a /srv/labshare/case.txt ~/lab/week18/case.before.txt
sudo sha256sum /srv/labshare/case.txt > ~/lab/week18/before.sha256
sudo ufw status numbered

2. Simulate an unauthorized-looking change

UBU01 • Bash; foreground server
date -u
printf "SIMULATED UNAPPROVED CHANGE W18\n" | sudo tee -a /srv/labshare/case.txt
sudo sh -c 'cd /srv/labshare && python3 -m http.server 8088 --bind 10.77.0.11'

This exposes only dummy files on a lab port. In another UBU01 console or SSH session, add a temporary ufw allow rule from 10.77.0.12 to TCP 8088. From UBU02 request http://10.77.0.11:8088/case.txt and record the status. The simulation is staged; do not report it as real compromise.

3. Preserve before stopping the process

Use a second UBU01 session. If UBU02 is used for SSH, use the key from Week 6. Capture process, socket, file hash, and UTC time:

UBU01 • Bash
mkdir -p ~/lab/week18
date -u > ~/lab/week18/collection-time.txt
ps -ef > ~/lab/week18/processes.txt
sudo ss -lntup > ~/lab/week18/sockets.txt
sudo sha256sum /srv/labshare/case.txt > ~/lab/week18/file-hash.txt
sudo journalctl --since "20 minutes ago" --no-pager > ~/lab/week18/journal.txt

Record collector, source, collection method, timezone, and limits. This is basic triage, not a forensic disk acquisition.

4. Contain and verify

Delete only the temporary ufw 8088 allow rule by its current displayed number. From UBU02 repeat the HTTP request with --max-time 5 and prove it is blocked. Preserve console access. Return to the foreground Python process and press Ctrl+C. Verify 8088 is no longer listening. Do not kill unrelated processes by broad name matching.

5. Restore and investigate the gap

Restore case.txt from the pre-simulation copy and verify its original hash and permissions. Confirm normal nginx HTTP still works from UBU02. If reviewing FIM, shut down UBU02 and start WAZUH01; inspect what the agent retained or detected later. Explain why an offline manager means you cannot assume a complete realtime timeline.

UBU01 • Bash
sudo cp -a ~/lab/week18/case.before.txt /srv/labshare/case.txt
sudo sha256sum -c ~/lab/week18/before.sha256
sudo ls -l /srv/labshare/case.txt

6. Deliver an incident report

Include scope, impact (dummy data only), observed facts, hypothesis, containment, evidence preserved, recovery tests, root cause of the simulation, and two improvements. Identify what a real organization would need beyond this lab: authority, communications, legal/HR coordination where appropriate, and forensic expertise. Do not invent exfiltration or attacker attribution from a request log.

Pass this week

  • Evidence manifest and timeline
  • Contained 8088 with normal service preserved
  • Recovery hash and incident report

Explain without the guide

  • Why capture process details before stopping it?
  • What distinguishes observed access from proven data exfiltration?

If something fails

No second console available: connect by SSH from UBU02 before starting the foreground server. Permission errors writing evidence: keep output in your home directory and apply sudo to the data source, not a broad interactive root session.

Optional practice · 0–6 extra hours

Ask the mentor to change one detail—different port or a stopped service—and repeat diagnosis without seeing the simulation steps.
