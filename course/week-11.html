Week 11 / Detection

Deploy your security monitoring stack

6 hours core+ 0–6 hours practicePrerequisite: Week 10

Wazuh’s agent observes an endpoint. Its manager parses events and applies rules. Its indexer stores searchable data. Its dashboard presents it. Installing the dashboard is not the same as proving collection, detection, or useful investigation.

Power-on plan: WAZUH01 only during installation: 8 GB fixed RAM, 4 vCPU, 80 GB disk. Later add UBU01 2 GB. Keep all other guests off. Host needs roughly 5–6 GB free headroom; measure actual pressure.

For dashboard access and file transfers, use the complete temporary management procedure in the lab handbook, including the explicit host key path and cleanup checks.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

1. Build WAZUH01

Repeat the Ubuntu installation procedure with VM/hostname WAZUH01/wazuh01, 8192 MB fixed RAM, 4 processors, 80 GB disk, and Ubuntu 24.04 Server. Use Default Switch for installation and updates. Install curl, nano, openssh-server, and ufw. Do not install Docker or another search stack here. If the host is already paging heavily with this VM alone, close apps or arrange a RAM upgrade/mentor-provided server before proceeding; do not quietly under-allocate Wazuh.

2. Install a recorded release

The official quickstart checked for this edition uses the 4.14 release family. Open it before installation and check supported Ubuntu versions and any changed instructions. Do not mix a newer agent with an older manager. In the guest run:

WAZUH01 • Bash, update mode
curl --fail --show-error --location -o wazuh-install.sh https://packages.wazuh.com/4.14/wazuh-install.sh
less wazuh-install.sh
sudo bash ./wazuh-install.sh -a

q exits less. The installer requires internet and may take time; review failures rather than repeatedly rerunning it. Store the generated credentials and installation archive privately. Do not paste installation output containing passwords into the notebook. Record installed package versions with dpkg-query -W wazuh-manager wazuh-indexer wazuh-dashboard.

3. Verify each component

WAZUH01 • Bash
sudo systemctl is-active wazuh-manager wazuh-indexer wazuh-dashboard filebeat
free -h
df -h /
sudo ss -lntp

Expect active services and sufficient free disk. If the dashboard is not ready, inspect that service’s journal. Keep the indexer’s 9200 and manager API’s 55000 ports unexposed to general clients.

4. Move to the private segment

Use Week 3’s network procedure to give WAZUH01 10.77.0.30/24, with no gateway/DNS, on CyberLab-Private. Enable ufw with default deny incoming and allow outgoing. Allow TCP 22 from 10.77.0.11 only, TCP 1514 and 1515 from 10.77.0.0/24, and TCP 443 from 10.77.0.0/24. Allow rules first, then enable ufw. Keep its console available. Start only UBU01 alongside it.

5. Reach the dashboard through a narrow temporary path

The real host cannot directly reach a Private switch. For setup only, shut down UBU01 and add a second Network Adapter in Hyper-V Settings → Add Hardware → Network Adapter, connected to Default Switch. Start it; identify the new interface with ip -br link and its MAC against Hyper-V. Add that interface to UBU01’s netplan with dhcp4: true while preserving eth0’s private static address. Apply. Temporarily allow SSH from the Default Switch host IP to the new interface using ufw. Find that host IP in host ipconfig under vEthernet (Default Switch). Do not enable IP forwarding or bridging on UBU01.

HOST • PowerShell; replace the IP token
ssh -i "$env:USERPROFILE\.ssh\cyberlab_host" -N -L 8443:10.77.0.30:443 learner@REPLACE_WITH_UBU01_DEFAULT_IP

Because UBU01 is key-only, first create a separate host SSH key using the explicit cyberlab_host key-generation command in the lab handbook if you lack one. Copy only its .pub line into UBU01’s ~/.ssh/authorized_keys via the VM console (nano); preserve the existing UBU02 public key. Set ~/.ssh to 700 and authorized_keys to 600. Verify UBU01’s host fingerprint before connecting. Open https://localhost:8443 in the host browser, accept only the known lab certificate after checking its fingerprint in the WAZUH01 console, then sign in. localhost will not match the lab certificate name; this is a scoped tunnel exception. A simpler alternative on a 32 GB host is a private Windows browser guest.

6. Close the temporary path

After dashboard work, close the SSH tunnel with Ctrl+C. Shut UBU01 down and remove only its added Default Switch adapter. Remove the corresponding netplan entry and temporary host-SSH ufw rule in its console. Verify the private-only state. This temporary management procedure is reused for dashboard sessions; no vulnerable container or active scan may run while it is connected. Keep Wazuh package upgrades coordinated; review official release guidance before updating the manager and agents.

Pass this week

  • Component/service and version inventory
  • Dashboard screenshot without secrets
  • Memory measurement and management-path diagram

Explain without the guide

  • Where does parsing occur and where is data searched?
  • Why is dashboard login not a detection test?

If something fails

Host paging: stop other VMs; if WAZUH01 + UBU01 is still impractical, use a mentor server or RAM upgrade. Tunnel failure: test UBU01 → 10.77.0.30:443, then host → UBU01 SSH. No listener on 8443: the tunnel is not running.

Optional practice · 0–6 extra hours

Draw failure symptoms for agent, manager, indexer, and dashboard separately. Explain which service you would inspect first for each symptom.
