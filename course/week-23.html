Week 23 / Cloud

Cloud foundations, access, and cost controls

6 hours core+ 0–6 hours practicePrerequisite: Week 22

Cloud changes who operates each layer; it does not remove your responsibility for identity, data, configuration, and monitoring. Azure has a management plane for resources and separate data-plane permissions. A budget alert is not a hard spending cap.

Power-on plan: Windows host browser only. Local VMs off. Default cloud track is Azure; the mentor provides a dedicated learning subscription or tightly scoped sandbox.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

Expanded track: See the six security-platform labs and schedule for Elastic, Splunk, and Security Onion. Budget these hours separately from the core; complete their comparison report for the final review.

1. Mentor provisions the boundary

The mentor signs in to Azure and creates a dedicated resource group rg-cyberlab-learner in an agreed region. Use a separate learner identity protected by MFA. Assign Contributor only at this resource group for creation labs; the mentor retains role-assignment and billing administration. Do not use an employer production subscription or share the subscription owner password. Record tenant, subscription, group, and region privately.

2. Inspect your effective access

Learner: sign in at portal.azure.com → Directory + subscriptions and select the intended tenant/subscription. Open Resource groups → rg-cyberlab-learner → Access control (IAM) → View my access. Record the scope and role. Contributor can manage resources but cannot generally assign roles. Do not attempt changes outside the group.

3. Set a budget before resources

Mentor: open Cost Management at the subscription or supported resource-group scope → Budgets → Add. Choose an agreed monthly amount in the subscription’s billing currency, start/end dates, and actual-cost alerts at 50%, 80%, and 100% to the mentor. Verify recipients and save. Check the Azure pricing calculator for a small Linux VM, managed disk, public IPv4, and minimal storage in the selected region. Record an estimate, not a promise of free service. Budget evaluation and cost reporting can be delayed; they do not stop resource creation.

4. Create a safe management event

Open the resource group → Tags. Add Course=CyberLab and Owner=Learner, then Save. Open Activity log, set the recent time range, and locate the write operation. Expand it and identify actor, operation, status, timestamp, and correlation ID. Export the event privately. This records a management action, not every data read inside a workload.

5. Build the cloud worksheet

Write the shared responsibility for five layers: physical hardware, guest OS patching, identity, network rules, and data access. Record the maximum agreed lab duration, who monitors spend, cleanup owner, and the exact resource-group name. Set a calendar reminder yourself before deploying the next lab; do not rely on memory.

6. Gate for paid resource creation

Show the mentor the selected subscription, role scope, budget settings, region, and calculator estimate. Continue only after the mentor supplies the agreed cloud access and spending boundary. If cloud access is not ready, repeat the Week 22 capstone or local TLS lab; do not create a personal paid account just to stay on schedule.

Pass this week

  • Scoped learner access and MFA confirmation
  • Budget/estimate/cleanup worksheet
  • An attributable cloud management event

Explain without the guide

  • Why is Contributor not the same as Owner?
  • What does the budget fail to prevent?

If something fails

Cannot create a budget: the learner role may lack billing access; the mentor configures it. Wrong directory: switch tenant/subscription before diagnosing permissions. A quota or regional SKU restriction is not solved by choosing a much more expensive machine.

Optional practice · 0–6 extra hours

Compare this resource-group boundary with an AWS account/IAM boundary at a conceptual level; do not deploy a second cloud.
