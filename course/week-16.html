Week 16 / Detection

Integrate network alerts and investigate a case

6 hours core+ 0–6 hours practicePrerequisite: Week 15

Integration requires a chain of evidence: packet → sensor JSON → agent collection → manager rule → searchable alert → analyst decision. Each boundary can fail independently. A case report distinguishes observed facts, hypotheses, and unknowns.

Power-on plan: WAZUH01 8 GB + UBU01 2 GB. Generate test traffic from WAZUH01 itself; UBU02 and Windows off.

For dashboard access and file transfers, use the complete temporary management procedure in the lab handbook, including the explicit host key path and cleanup checks.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

Expanded track: See the six security-platform labs and schedule for Elastic, Splunk, and Security Onion. Budget these hours separately from the core; complete their comparison report for the final review.

1. Collect Suricata JSON

On UBU01 back up ossec.conf.

Inside its existing ossec_config add the following localfile block, preserving the FIM settings. Restart the agent and inspect its log.

UBU01 • Wazuh agent ossec.conf
<localfile>
  <log_format>json</log_format>
  <location>/var/log/suricata/eve.json</location>
</localfile>
UBU01 • Bash
sudo systemctl restart wazuh-agent
sudo tail -30 /var/ossec/logs/ossec.log

2. Produce fresh sensor evidence

  1. Use Week 15’s foreground Suricata command on UBU01.
  2. On WAZUH01 run ping -c 3 10.77.0.11.
  3. Stop the foreground sensor after the test.

Check: Verify current EVE alerts locally before looking in the dashboard.

3. Verify the manager layer

WAZUH01 • Bash
sudo tail -100 /var/ossec/logs/alerts/alerts.json | jq -c 'select(.rule.groups[]? == "suricata")'

A short tail can miss earlier alerts.

  1. If necessary search the file for CYBERLAB ICMP request using sudo grep.
  2. In the dashboard use rule.groups:suricata and agent.name:UBU01.
  3. Expand the event; confirm the signature ID, source 10.77.0.30, destination 10.77.0.11, and timestamp.

4. Build a case from evidence

  1. Create case LAB-016.
  2. Write a UTC timeline: approved test start, packet generation, EVE event, manager alert, analyst review.

Assess whether the activity is expected.

  1. Attach only sanitized excerpts with hashes for original files kept privately.
  2. Close as authorized training activity with the evidence supporting that decision.

5. Exercise a collection failure

Back up the working agent config.

Temporarily change only the Suricata localfile location to /var/log/suricata/not-present.json. Restart the agent, generate one ping test, and show that local Suricata evidence exists while central visibility does not.

  1. Restore the correct path, restart the agent, and generate a new test to prove recovery.
  2. Do not assume every event during the gap will be backfilled.

Pass this week

  • Source-to-alert trace
  • A completed LAB-016 case
  • Collection-gap diagnosis and fresh recovery test

Explain without the guide

  • What evidence justifies closing the case?
  • At which layer did the deliberate failure occur?

If something fails

Native integration schema differs across releases: inspect the actual EVE object and manager decoder output with wazuh-logtest. Do not force a hardcoded dashboard query to fit absent fields; document actual field names.

Optional practice · 0–6 extra hours

Compare one FIM event and one network event in the same timeline. Explain why correlation in time does not alone prove causation.
