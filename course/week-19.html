Week 19 / Response

Back up data and prove a restore

6 hours core+ 0–6 hours practicePrerequisite: Week 18

Recovery point objective (RPO) describes tolerable data loss in time. Recovery time objective (RTO) describes tolerable restoration time. A backup that cannot be restored is an unproven control. A repository on the same disk is useful for practice but does not survive loss of that disk.

Power-on plan: UBU01 only, 2 GB. Optional UBU02 for a later remote repository.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

Expanded track: See the six security-platform labs and schedule for Elastic, Splunk, and Security Onion. Budget these hours separately from the core; complete their comparison report for the final review.

1. Install restic and prepare dummy data

Install restic with sudo apt install restic in update mode, record restic version, then return private. These exercises use your home directory so they do not alter a live service.

Ubuntu guest • Bash
mkdir -p ~/lab/week19/source
printf "customer,classification\nDemo Person,dummy\n" > ~/lab/week19/source/records.csv
sha256sum ~/lab/week19/source/records.csv > ~/lab/week19/original.sha256

2. Initialize an encrypted repository

Ubuntu guest • Bash
restic -r ~/lab/week19/repository init
restic -r ~/lab/week19/repository backup ~/lab/week19/source
restic -r ~/lab/week19/repository snapshots

Choose a unique repository password and store it in your password manager. Do not put it into shell history or the evidence report. Record the snapshot ID and time. The snapshot is not a Hyper-V checkpoint.

3. Simulate file loss safely

Ubuntu guest • Bash
mv ~/lab/week19/source/records.csv ~/lab/week19/records.simulated-loss
ls -la ~/lab/week19/source
restic -r ~/lab/week19/repository restore latest --target ~/lab/week19/restore

The restore target is separate from the original location. restic reconstructs the backed-up path under that target; for learner it is normally ~/lab/week19/restore/home/learner/lab/week19/source/records.csv. Find the actual restored file before comparing.

4. Validate content, not just the success message

Ubuntu guest • Bash
find ~/lab/week19/restore -name records.csv -type f
sha256sum ~/lab/week19/restore/home/learner/lab/week19/source/records.csv
cat ~/lab/week19/original.sha256
restic -r ~/lab/week19/repository check

The hash must match the original. Read the restored CSV and confirm it is usable. Record the restore start/end times. Copy the verified restored file back into source after checking the destination.

5. Explain the failure domains

This repository and its source share UBU01’s disk and the same physical SSD. It protects the exercise against a removed file, not VM destruction, SSD failure, theft, or an administrator deleting both. Write a real backup design with a separate device/location, protected credentials, restricted deletion, tested restores, and a retention schedule. Do not claim the lab has implemented those controls.

6. Preserve the course work

Shut UBU01 down and use Hyper-V Manager → Export to a directory under C:\CyberLab\Exports with enough free space. An export on the same SSD is still not an off-device backup. If an external drive is available, copy the export there and test importing a copy with a new unique VM ID on a disconnected network. Never boot an imported copy with the same IP alongside the original.

Pass this week

  • Snapshot and repository check
  • Restored-file hash and measured recovery time
  • Backup design explaining shared-disk risk

Explain without the guide

  • How much data could be lost after a daily backup?
  • What happens if the repository password is lost?

If something fails

Restored file “missing”: inspect the reconstructed directory path with find. Wrong hash: check snapshot time and selected file. Repository locked: confirm no active restic process before following documented recovery; do not delete lock files blindly.

Optional practice · 0–6 extra hours

Build an SFTP repository on UBU02, perform another restore, and explain why two VMs on one SSD still share a physical failure domain.
