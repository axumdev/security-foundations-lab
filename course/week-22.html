Week 22 / Assessment

Rebuild, document risk, and pass the local capstone

6 hours core+ 0–6 hours practicePrerequisite: Week 21

Professional competence includes explaining choices, accepting limits, and restoring a working system from documented steps. This week joins the layers you have practiced. Documentation is tested when someone else uses it.

Power-on plan: Use staged profiles: Linux 4 GB, identity 8 GB, monitoring 10 GB. This is also the scheduled catch-up week before cloud.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

Expanded track: See the six security-platform labs and schedule for Elastic, Splunk, and Security Onion. Budget these hours separately from the core; complete their comparison report for the final review.

1. Select a business scenario

Use a fictional small training center with an internal web page, two staff roles, dummy records, and a requirement to detect unauthorized file changes. Write five requirements: private access, least privilege, encrypted transport, observable changes, and recoverable data. State a lab recovery target of 30 minutes for the dummy file and explain it is an exercise target, not a measured guarantee yet.

2. Produce the architecture

Draw the host, private switch, every VM/IP, each service, allowed ports, and data flow. Add a second diagram showing which machines are powered on together. Mark the temporary dashboard management path and the conditions for removing it. Include the Windows replay limitation.

3. Run acceptance tests

Demonstrate from saved instructions: UBU02 reaches nginx; SSH password login is denied while key login works; TLS is verified with the lab trust file; a file change produces FIM evidence; a sensor ping reaches central monitoring; a backup restore matches its original hash. Renew the Week 10 lab certificate if it expired. Perform tests in separate power profiles.

4. Diagnose one unknown fault

Your mentor chooses a single fault from the mentor guide and records the original setting privately. You get 45 minutes to state the symptom, collect evidence, form a hypothesis, repair one cause, and rerun the acceptance test. No random reinstalling. If you cannot solve it, explain what you ruled out and what evidence you need next.

5. Write a five-item risk register

Include weak points you actually have: one physical SSD, intermittent central monitoring, evaluation-license lifetime, temporary dual-homed management, and limited network visibility. For each record likelihood/impact in plain language, current control, remaining risk, owner, next action, and review date. Do not disguise a known limitation as a completed control.

6. Hold a readiness review

Present for 15 minutes, then answer mentor questions for 15 minutes. Pass requires a correct network boundary, observed positive and negative tests, one successful restore, and at least 8/10 on the rubric. If a required gate fails, use the remaining week for repair and repeat; postpone cloud until the foundation is sound.

Pass this week

  • Architecture and power profiles
  • Six acceptance tests with evidence
  • Risk register and local capstone score

Explain without the guide

  • Which control would you improve first with more RAM or budget?
  • What would fail if the host SSD died?

If something fails

Old evidence does not prove the current state. Re-run a small fresh test when configuration or versions changed. If multiple faults appear, return to a known baseline and document the divergence before continuing.

Optional practice · 0–6 extra hours

Ask another person to follow one runbook without verbal help. Record unclear steps and improve the guide.
