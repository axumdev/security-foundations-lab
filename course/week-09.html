Week 09 / Systems

Identity lifecycle and Group Policy

6 hours core+ 0–6 hours practicePrerequisite: Week 08

A group expresses an access role. An organizational unit (OU) scopes administration and policy. A Group Policy Object (GPO) is a configuration applied through scope and processing rules. Creating a policy is not proof that it reached the intended computer.

Power-on plan: DC01 + WIN01, 8 GB total, private switch.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

1. Create a small organization

On DC01 open Server Manager → Tools → Active Directory Users and Computers. Under corp.example.test create OUs LabUsers and LabServers (right-click domain → New → Organizational Unit). In LabUsers create user Abebe with sign-in name abebe and a unique temporary password; require password change at next logon. Create a Global Security group CaseReaders and add Abebe as a member. Move WIN01 from Computers into LabServers. Keep DC01 in Domain Controllers.

2. Exercise joiner/mover/leaver access

On WIN01, as Administrator, add CORP\CaseReaders read access to C:\LabData using the Security dialog. Preserve administrator/SYSTEM entries. Launch a prompt as Abebe with runas /user:CORP\abebe powershell; change the password through interactive sign-in if required first. Prove reading case.txt succeeds and writing fails. On DC01 remove Abebe from CaseReaders. Close all Abebe sessions and sign in anew before testing denial; old tokens can retain membership. Re-add membership for the next exercise.

3. Apply a visible computer policy

On DC01 open Group Policy Management. Expand Forest → Domains → corp.example.test. Right-click LabServers → Create a GPO in this domain, and Link it here. Name it Lab-Logon-Notice. Edit → Computer Configuration → Policies → Windows Settings → Security Settings → Local Policies → Security Options. Set “Interactive logon: Message title for users attempting to log on” to CyberLab and the message text to Authorized training VM only. Do not edit Default Domain Policy for this lab.

4. Prove actual application

WIN01 • administrator PowerShell
gpupdate /force
New-Item -ItemType Directory -Force C:\LabEvidence
gpresult /h C:\LabEvidence\week09-policy.html

Sign out and verify the notice at sign-in. Open the report and find Lab-Logon-Notice under applied computer GPOs. This is stronger evidence than a screenshot of the policy editor alone.

5. Disable and restore an account

On DC01 right-click Abebe → Disable Account. Sign out of Abebe sessions and attempt a new domain sign-in while DC01 is running. Expect denial. Re-enable the account and prove a new sign-in succeeds. Record that disabling an account does not necessarily terminate already established sessions immediately. Unlink Lab-Logon-Notice if you want to remove the banner, then run gpupdate and verify.

Pass this week

  • Group membership access tests after new logons
  • Applied-policy report
  • Account-disable test and limits

Explain without the guide

  • How does group membership differ from OU placement?
  • Why are existing sessions relevant to offboarding?

If something fails

GPO not applied: verify WIN01 is in LabServers, link enabled, DNS/DC reachable, and computer policy settings used. Inspect gpresult before changing security filters.

Optional practice · 0–6 extra hours

Create a separate helpdesk identity and discuss narrowly delegated password resets. Document the proposed scope before implementing optional delegation.
