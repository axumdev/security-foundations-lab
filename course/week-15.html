Week 15 / Detection

Build a network sensor with Suricata

6 hours core+ 0–6 hours practicePrerequisite: Week 14

A network intrusion detection system interprets traffic visible at its capture interface. Visibility is a topology property. Putting a sensor VM on a switch does not guarantee it sees every conversation. This lab captures traffic addressed to UBU01, then demonstrates a controlled ICMP detection.

Power-on plan: UBU01 sensor/web server + UBU02 generator, 4 GB total. Wazuh off during packet generation.

Your week: Session A (2 h): read, prepare, begin the first steps. Session B (2 h): finish the build and tests. Session C (2 h): troubleshoot, write evidence, and complete mentor review. These are planning estimates; use extra hours for repeats. If a gate fails, carry it forward before dependent labs.

Expanded track: See the six security-platform labs and schedule for Elastic, Splunk, and Security Onion. Budget these hours separately from the core; complete their comparison report for the final review.

1. Install the sensor

Put UBU01 in update mode with nginx stopped. Use OISF’s stable repository, not development builds. Record the installed version.

UBU01 • Bash, update mode
sudo apt install software-properties-common
sudo add-apt-repository ppa:oisf/suricata-stable
sudo apt update
sudo apt install suricata jq
suricata --build-info
sudo systemctl stop suricata

Return UBU01 and UBU02 to CyberLab-Private. Confirm the capture interface using ip -br address. Examples below use eth0.

2. Add one transparent rule

UBU01 • Bash
sudo mkdir -p /etc/suricata/rules
sudo nano /etc/suricata/rules/cyberlab.rules
UBU01 • cyberlab.rules
alert icmp any any -> 10.77.0.11 any (msg:"CYBERLAB ICMP request"; itype:8; sid:1000001; rev:1;)

The rule alerts on an echo request to this VM. It is intentionally a demonstration, not evidence of attack. sid identifies the signature; rev tracks your revisions.

3. Validate configuration

Back up /etc/suricata/suricata.yaml. Open it and set HOME_NET to "[10.77.0.0/24]". In the existing eve-log output verify enabled: yes and that types includes alert. Keep the other defaults. Run the test using only your training rule:

UBU01 • Bash
sudo suricata -T -c /etc/suricata/suricata.yaml -S /etc/suricata/rules/cyberlab.rules

Uppercase -S loads only the given rule file for this controlled test. Require a successful configuration test before capture.

4. Capture a predictable event

UBU01 • Bash; foreground, replace interface if needed
sudo suricata -c /etc/suricata/suricata.yaml -S /etc/suricata/rules/cyberlab.rules -i eth0
UBU02 • Bash
ping -c 3 10.77.0.11

Return to UBU01 and press Ctrl+C after the ping completes. Inspect alerts:

UBU01 • Bash
sudo jq -c 'select(.event_type=="alert") | {timestamp,src_ip,dest_ip,signature:.alert.signature,sid:.alert.signature_id}' /var/log/suricata/eve.json

Expect your signature and source 10.77.0.12. Repeated runs append data; filter by current timestamp to avoid counting old results.

5. Run a negative test

Start the same foreground sensor again. From UBU02 request HTTP from UBU01 instead of pinging: curl -I http://10.77.0.11. If nginx is stopped, start it first. Stop capture and verify this HTTP request did not create a new ICMP signature alert. Logs may still contain non-alert flow/HTTP records.

6. Save the configuration and scope

Preserve your rule, a sanitized alert, the tested version, and a diagram showing the capture point on UBU01. Explain that this setup observes its own traffic, not UBU02-to-another-VM traffic. Do not invent whole-network coverage. Keep the service stopped; next week uses the same explicit foreground capture command.

Pass this week

  • Successful Suricata configuration test
  • ICMP positive and HTTP negative test
  • Capture-point diagram

Explain without the guide

  • What could a healthy sensor still fail to see?
  • Why is ping not automatically malicious?

If something fails

No packets: wrong interface/switch or generator target. Packets but no alerts: confirm rule loaded, destination, ICMP type, output path, and current timestamps. “Device busy” or duplicate records: stop the packaged service before foreground capture.

Optional practice · 0–6 extra hours

Use a saved PCAP with suricata -r and a new output directory. Compare replay time to packet event time. Port mirroring is an optional later topology exercise.
